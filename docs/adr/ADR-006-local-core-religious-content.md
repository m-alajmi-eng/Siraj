# ADR-006: استقلالية كاملة للمحتوى الديني الجوهري (بلا اعتماد خارجي)

**الحالة:** مُعتمَد — قيد التنفيذ التدريجي

## المشكلة
سراج يعتمد حالياً على خدمات خارجية (alquran.cloud، Supabase جزئياً) لعرض
محتوى ديني جوهري متكرر الاستخدام: نص القرآن، ترجماته، التفسير، معاني
الكلمات. هذا الاعتماد يعني: توقف الخدمة الخارجية = تعطّل جوهر التطبيق —
خطر غير مقبول لتطبيق ديني.

## القرار
تصنيف محتوى القرآن وملحقاته إلى فئتين واضحتين:

**١. محتوى جوهري أساسي → محلي بالكامل، مملوك لسراج، بلا أي اعتماد خارجي:**
- نص القرآن العربي (حالياً من alquran.cloud → ينتقل لملف JSON محلي)
- ترجمات القرآن للـ15 لغة (حالياً من alquran.cloud → تنتقل لملفات JSON محلية)
- التفسير الميسّر (حالياً في Supabase → ينتقل لملف JSON محلي)
- علامات التجويد الملوّنة (جديد — يُبنى محلياً من مصدر خارجي مرة واحدة
  ثم يُخزَّن كأصل ثابت، لا يُستدعى حياً من أي API)
- معاني الكلمات (غريب القرآن) — ميزة جديدة، محلية من البداية
- صوت الأذان — ملف صوتي واحد مضمَّن محلياً
- حساب أوقات الصلاة — حساب فلكي محلي، بلا اعتماد على API خارجي

**٢. محتوى إثرائي واسع → اعتماد خارجي مقبول (IslamHouse):**
- كتب ومقالات المكتبة الشاملة
- صوتيات المحاضرات والخطب
- فيديوهات

## سبب القرار
- المحتوى في الفئة الأولى صغير الحجم نسبياً (نص، لا ملفات وسائط ضخمة)،
  ثابت لا يتغيّر، وحسّاس دينياً بدرجة لا تحتمل انقطاع خدمة خارجية.
- المحتوى في الفئة الثانية ضخم الحجم (آلاف الكتب/الساعات الصوتية)، يتحدّث
  باستمرار من مصدره (IslamHouse)، ونسخه بالكامل محلياً يضاعف تكلفة
  التخزين والصيانة بلا فائدة تناسب الخطر المُتجنَب.
- هذا يطبّق مبدأي "Offline First" و"Religious Content Accuracy Over
  Speed" و"Minimize Vendor Lock-in" المُوثَّقة في SIRAJ_PRINCIPLES.md
  بأوضح صورة ممكنة.

## خطة التنفيذ المرحلية (بالترتيب المتفق عليه)
لتفادي فتح جبهات متعددة معاً، نُنجز عنصراً واحداً بعمق قبل الانتقال للتالي:

- [ ] **المرحلة 1 (جارية الآن):** التجويد الملوّن — جلب نص `quran-tajweed`
  من alquran.cloud **مرة واحدة لكل السور الـ114**، تحليله بـ parser مبني
  على جدول `vipafattal/TajweedParser`، وحفظه كملف JSON محلي ثابت ضمن
  `assets/data/quran_tajweed.json`. بعد هذه الخطوة، لا نستدعي alquran.cloud
  لهذا الغرض مرة أخرى وقت التشغيل.
- [ ] **المرحلة 2:** نقل نص القرآن العربي + الترجمات الـ15 لغة إلى ملفات
  JSON محلية (نفس أسلوب المرحلة 1: جلب مرة واحدة، تخزين دائم).
- [ ] **المرحلة 3:** نقل التفسير الميسّر من Supabase إلى ملف JSON محلي.
- [ ] **المرحلة 4:** فحص الوضع الحالي لأوقات الصلاة والأذان (هل يعتمدان
  على API خارجي الآن؟) وبناء حساب محلي إن لزم.
- [ ] **المرحلة 5:** ميزة معاني الكلمات (غريب القرآن) — بناء جديد كامل.
- [ ] **المرحلة 6 (مستقبلية، خارج هذا الـADR):** قصص الأطفال — ميزة جديدة
  منفصلة تماماً، تُكتب من الصفر.

**ملاحظة توضيح مطلوبة من المطوّر:** "بوابة القرآن" المذكورة ضمن الطلب
الأصلي تحتاج توضيحاً — هل تُقصد بها بوابة غير المسلمين الموجودة فعلاً
(مكتملة)، أم ميزة منفصلة جديدة؟ يُحسم هذا قبل بدء المرحلة 6.

## متى نعيد تقييمه
- عند اكتمال كل المراحل أعلاه، يُغلق هذا الـ ADR كمُنفَّذ بالكامل.
- إذا ظهر لاحقاً محتوى جوهري جديد لم يُذكر هنا، يُضاف كمرحلة جديدة في
  نفس هذا الملف، لا في ADR منفصل، حفاظاً على وحدة الخطة.
