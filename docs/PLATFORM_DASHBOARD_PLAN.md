# خطة: المنصة + لوحة التحكم (Web Platform + Admin Dashboard)

قرار موثّق (يوليو 2026): سراج يتوسّع ليكون **تطبيقاً + منصة ويب**، لا
تطبيق جوال فقط. هذا قرار منتج واعٍ بأسباب حقيقية (لا بناء استباقي فارغ).

---

## لماذا (الأسباب الحقيقية التي تبرّر الإضافة)
1. **الوصول الشامل:** خدمة من لا يملك هاتفاً ذكياً، أو يفضّل الكمبيوتر
   للقراءة والبحث المطوّل (تجربة أفضل للدراسة والتدبّر على شاشة كبيرة).
2. **التحكم الكامل بالمشروع:** لوحة إدارة لتحديث المحتوى وإضافة تطويرات
   بدون تعقيد، بدل التعديل اليدوي في الملفات/Git فقط.
3. **مراقبة النظام:** متابعة صحة التطبيق، الأخطاء، الاستخدام.
4. **بيانات حقيقية للتطوير:** فهم سلوك المستخدمين (بخصوصية محترمة) لتوجيه
   قرارات التطوير المستقبلية ببيانات لا تخمين.

---

## المبدأ الحاكم: منصة بلا تعقيد
"منصة" هنا لا تعني بنية تحتية ضخمة. الأساس الموجود (Supabase) يكفي معظم
الطريق. نبني بأبسط شكل يحقق الأهداف الأربعة أعلاه، ونتوسّع عند الحاجة
المقيسة فقط (نفس مبدأ SIRAJ_PRINCIPLES: لا أداة قبل ألم حقيقي).

## المكوّنات (مرتّبة بالأولوية)

### 1. منصة الويب للمستخدم النهائي (Web App)
- **الأبسط تقنياً:** Flutter Web من نفس القاعدة الحالية (كود مشترك،
  صيانة واحدة) - المشروع أصلاً يدعم web (تحقّقنا: Supported Platforms
  تشمل web). يحتاج تكييف الواجهات للشاشة الكبيرة (responsive).
- **البديل إن احتجنا أداءً/SEO أفضل:** موقع منفصل (Next.js مثلاً)
  يتصل بنفس Supabase - يُقيَم فقط إن ثبت قصور Flutter Web فعلياً.
- يخدم: القراءة، البحث، التصفح على الكمبيوتر (تجربة دراسة مريحة).

### 2. لوحة التحكم الإدارية (Admin Dashboard)
- **المرحلة الأولى (جاهزة الآن مجاناً):** Supabase Studio المدمج -
  إدارة الجداول، المستخدمين، SQL. كافٍ للبداية بلا أي بناء.
- **المرحلة الثانية (عند الحاجة):** لوحة مخصصة (تطبيق ويب صغير يتصل
  بنفس Supabase) لإدارة المحتوى بواجهة أسهل من Supabase الخام -
  إضافة/تعديل محتوى، مراجعة، نشر. تُبنى حين يصبح تحديث المحتوى متكرراً.

### 3. المراقبة (Observability)
- Firebase Crashlytics (قرار سابق) للأخطاء والاستقرار.
- تحليلات محترمة للخصوصية (حد أدنى) لفهم الاستخدام.

### 4. البيانات الحقيقية (Analytics بخصوصية)
- جمع بيانات استخدام مجمّعة (لا تتبّع فردي متطفّل) تحترم مبدأ الخصوصية
  المعلن: ما المحتوى الأكثر قراءة؟ أي ميزات تُستخدم؟ أين يتوقف الناس؟
- تستخدم لتوجيه التطوير، لا لبيعها (المشروع خيري، بلا إعلانات).

## الترتيب المقترح للتنفيذ (بعد إنهاء قسم القرآن والختمة الحاليين)
1. تفعيل Flutter Web للمشروع الحالي + تكييف responsive أساسي
2. Crashlytics + تحليلات خصوصية (كانت مجدولة أصلاً قبل الإطلاق)
3. تقييم: هل Supabase Studio يكفي كلوحة تحكم، أم نحتاج مخصصة؟
4. بناء لوحة التحكم المخصصة (إن ثبتت الحاجة) بأبسط شكل
