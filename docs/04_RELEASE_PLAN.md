# 04 — خطة الإطلاق (Release Plan)

> إطلاق متدرّج بمعايير انتقال صارمة. **لا ننتقل لمرحلة قبل استيفاء معايير
> الخروج من سابقتها كاملةً** — هذه حماية من إطلاق متسرّع يضر السمعة
> (وسمعة تطبيق ديني رأس ماله الوحيد).

## نظرة عامة

```
Dev (الآن) → Alpha (داخلي) → Beta (مغلق) → RC → v1.0 → Post-launch
```

---

## المرحلة 0: Dev — حيث نقف الآن

**الهدف:** إغلاق P0 التقنية وإنهاء نواة المنتج (مصحف + ختمة).

**معايير الخروج (كلها إلزامية):**
- ⬜ `flutter build apk --release` ينجح نظيفاً (C1)
- ⬜ GitHub Actions يعمل: analyze + tests + APK لكل push
- ⬜ وضع صفحات المصحف مكتمل بقراره النهائي (مصدر التخطيط محسوم ومنفّذ،
  اسم السورة صحيح، أزرار تنقّل، تفاعل ضغط الآية)
- ⬜ الختمة مراحل 3–4 (القراءة تسجّل التقدم + شاشة التفاصيل)
- ⬜ اختبارات KhatmahPlan + الثوابت الدينية خضراء في CI
- ⬜ نص الشهادة متحقق شرعياً والعلم مزال

**المخاطر:** إغراء إضافة ميزات جديدة (الحارس: هذه الوثيقة) · تعقيد إصلاح Gradle
أكثر من المتوقع (خطة بديلة: استبدال flutter_qiblah بحساب اتجاه ذاتي بسيط —
الرياضيات معروفة).

## المرحلة 1: Alpha — داخلي (أنت + علاء + 3-5 أشخاص ثقة)

**الهدف:** أول استخدام حقيقي خارج بيئة التطوير. **التوزيع:** APK مباشر من
CI (لا متاجر بعد).

**معايير الدخول:** خروج Dev كاملاً. **المدة الإرشادية:** أسبوعان.

**أثناءها:** Crashlytics مفعّل من اليوم الأول · جمع الملاحظات في GitHub
Issues (يبدأ سجل رسمي بدل الذاكرة) · اختبار على جهاز Android ضعيف حقيقي +
iPhone حقيقي (غير متوفرين حالياً — **يجب تدبيرهما**).

**معايير الخروج:**
- ⬜ صفر أعطال حرجة لمدة أسبوع متصل
- ⬜ كل ملاحظات Alpha الحرجة مغلقة
- ⬜ الختمة كاملة (مراحل 5–7: تذكيرات، توحيد قراءة، مشاركة)
- ⬜ حزمة القانوني منشورة (خصوصية + شروط + تراخيص + حذف حساب يعمل)
- ⬜ قرار قسم الأطفال منفّذ (إخفاء أو إكمال)
- ⬜ ترخيص الراديو محسوم (أو الميزة معلّقة مؤقتاً بقرار موثّق)

## المرحلة 2: Beta — مغلق (20–50 مستخدماً متنوعي اللغات والأجهزة)

**الهدف:** تحقق متعدد اللغات والأجهزة. **التوزيع:** Google Play Internal/
Closed testing + TestFlight (هذا يختبر مسار المتاجر نفسه مبكراً).

**أثناءها:** مراجعو لغات (شخص ثقة لكل لغة رئيسية: أردو، إندونيسي، تركي،
فرنسي...) يتحققون من الترجمات عيّنياً · قياس أداء فعلي (إقلاع/ذاكرة/تقليب
صفحات) وتوثيق الأرقام · اختبار offline كامل على أجهزة متنوعة.

**معايير الخروج:**
- ⬜ crash-free ≥ 99.5% (رقم Crashlytics فعلي)
- ⬜ تقليب الصفحات سلس على الجهاز الضعيف المرجعي (قياس موثّق)
- ⬜ مراجعة لغوية موثّقة لأعلى 6 لغات استخداماً
- ⬜ مراجعة شرعية موثّقة للتجويد الملوّن من مختص
- ⬜ Data Safety + Privacy Labels مقدَّمة ومقبولة في مسارات الاختبار

## المرحلة 3: RC (مرشَّح الإطلاق)

**الهدف:** تجميد الميزات؛ إصلاحات فقط. **المدة:** أسبوع–أسبوعان.

**معايير الخروج:** ⬜ صفر بلاغات حرجة أو عالية مفتوحة · ⬜ قائمة ما قبل
التقديم في 02_STORE_COMPLIANCE مكتملة 100% · ⬜ لقطات/أوصاف/تصنيف عمري
جاهزة · ⬜ خطة تراجع (rollback) مكتوبة.

## المرحلة 4: v1.0 — الإنتاج

إطلاق تدريجي (staged rollout 10%→50%→100% على Google Play) · مراقبة
Crashlytics يومياً أول أسبوعين · قناة استقبال بلاغات معلنة داخل التطبيق.

## ما بعد الإطلاق (v1.x)

بالترتيب الموثّق مسبقاً: تحسينات من ملاحظات المستخدمين الحقيقيين أولاً →
غريب القرآن (ADR-006 مرحلة 5، البيانات جاهزة: MuyassarGhareeb.docx) →
منصة الويب (PLATFORM_DASHBOARD_PLAN) → iPad/شاشات كبيرة → ثم تقييم
بقية ROADMAP ببيانات استخدام حقيقية لا تخميناً.

## v2.0 والرؤية البعيدة

تُقرَّر ببيانات v1 الحقيقية. المرشّحون الموثّقون: التجارب الأربع كاملة
(Reading/Mushaf/Study/Memorization)، مساعد التلاوة (ADR-005)، Huawei/
سطح المكتب. **القاعدة الثابتة:** لا ميزة v2 تُبنى قبل أن تثبت v1 جدواها
بولاء مستخدمين حقيقي.
