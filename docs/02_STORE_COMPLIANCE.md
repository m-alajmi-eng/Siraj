# 02 — امتثال المتاجر والمنصات (Store Compliance)

> تدقيق امتثال لكل المنصات المستهدفة حالياً ومستقبلاً. **تنبيه منهجي:**
> إرشادات المتاجر تتغيّر باستمرار — البنود أدناه مبنية على المعرفة العامة
> المستقرة؛ **يجب مراجعة الصفحات الرسمية قبل كل تقديم فعلي** (روابطها أدناه).
> حالة كل بند وفق ما يمكن التحقق منه من جلسات البناء فقط.

**المنصات:** الأساسية الآن: Android + iOS. مخطط لاحقاً (PLATFORM_DASHBOARD_PLAN):
Web/PWA + Linux (يعمل تطويرياً بالفعل). مستقبلية اختيارية: Huawei، Microsoft،
macOS، Windows.

## 1) Apple App Store — الجاهزية: 4/10

المرجع الرسمي: developer.apple.com/app-store/review/guidelines

### إلزامي (أسباب رفض مباشرة)
| البند | الحالة | التفصيل والخطوات |
|---|---|---|
| حذف الحساب داخل التطبيق (5.1.1v) | ❌ | لدينا Firebase Auth ⇒ إلزامي. بناء تدفق: إعدادات → حذف حسابي → تأكيد → حذف Auth + بيانات Supabase |
| سياسة خصوصية (رابط في App Store Connect وداخل التطبيق) | ⬜ | كتابة صفحة ويب + ربطها |
| App Privacy Labels (تصريح جمع البيانات) | ⬜ | حصر الفعلي: بريد (Auth)، موقع تقريبي (صلاة/قبلة — يُعالج محلياً)، لا تتبّع |
| نصوص أغراض الأذونات في Info.plist (NSLocationWhenInUsage...) | غير متحقق | مراجعة ios/Runner/Info.plist فعلياً |
| ATT (تتبّع) | ✅ لا ينطبق | لا إعلانات ولا تتبّع عبر تطبيقات — ميزة امتثالية تبسّط المراجعة |
| UIBackgroundModes=audio (إن استمر الراديو بالخلفية) | غير متحقق | يعتمد على سلوك audioplayers الحالي — اختبار فعلي مطلوب |
| الاستقرار (لا أعطال أثناء المراجعة) | ❌ | مرهون بإصلاح البناء C1 + Crashlytics + اختبار على جهاز حقيقي |
| اكتمال الوظائف (لا أقسام "قريباً" ظاهرة) | 🟡 | قسم الأطفال غير مكتمل — إخفاؤه من الإصدار الأول أو إكماله |
| الدفع داخل التطبيق | ✅ لا ينطبق | لا مشتريات إطلاقاً |
| المحتوى الديني (1.1) | ✅ منخفض الخطر | محتوى تعبّدي محترم؛ بوابة غير المسلمين تثقيفية غير هجومية |

### مستحسن
HIG للأحجام الكبيرة (iPad — مؤجَّل موثّق)، Dynamic Type، VoiceOver (غير
متحقق/غير مختبر)، لقطات شاشة لكل الأحجام، وصف متجر بـ 15 لغة (ميزة تسويقية).

### أخطار رفض خاصة بنا
حذف الحساب (الأعلى احتمالاً) · نقص Privacy Labels · تعطّل الراديو أثناء
المراجعة (يحتاج شبكة — يجب أن يفشل بلطف) · أداء iPad إن قُدّم كـ Universal.

## 2) Google Play — الجاهزية: 4/10

المرجع: play.google.com/console → Policy Center

### إلزامي
| البند | الحالة | التفصيل |
|---|---|---|
| إنتاج AAB موقَّع | ❌ محظور بـ C1 | إصلاح Gradle/Kotlin أولاً ثم إعداد توقيع release (غير متحقق وجوده) |
| Data Safety form | ⬜ | نفس حصر Apple Privacy Labels |
| سياسة خصوصية (رابط) | ⬜ | نفس صفحة Apple |
| حذف حساب (سياسة 2024+) | ❌ | نفس تدفق Apple + رابط ويب للحذف |
| POST_NOTIFICATIONS وقت التشغيل (Android 13+) | غير متحقق | إشعارات الصلاة لدينا مجدولة — يجب التحقق أن الطلب يظهر فعلياً |
| Target SDK حديث (مطلب سنوي متجدد) | غير متحقق | مراجعة android/app/build.gradle.kts |
| Foreground service بنوع mediaPlayback (راديو بالخلفية، Android 14+) | غير متحقق | مرتبط بقرار just_audio المجدول |
| الأذونات في Manifest مبررة كلها | غير متحقق | مراجعة AndroidManifest.xml |

### أخطار رفض خاصة بنا
البناء نفسه (قبل كل شيء) · Data Safety ناقص · ANR على أجهزة ضعيفة بسبب
تحليل JSON كبير عند الإقلاع (H3 — يحتاج قياساً) · خدمة خلفية غير معلنة للراديو.

## 3) Huawei AppGallery — مستقبلية (غير مستهدفة الآن)

نقطة حاسمة يجب معرفتها مبكراً: أجهزة Huawei الحديثة **بلا خدمات Google** —
أي **Firebase Auth وFCM لن يعملا**. الدخول لاحقاً يتطلب: بدائل HMS أو جعل
Auth اختيارياً بالكامل (التطبيق يعمل أصلاً بلا حساب — ميزة معمارية قائمة
تسهّل هذا). سوقها مهم لجمهورنا (آسيا/الخليج). القرار: مؤجَّل حتى ما بعد
الإطلاق الأساسي، ويُقيَّم وقتها بمراجعة رسمية لسياساتهم.

## 4) Microsoft Store / Windows — مستقبلية

Flutter يدعم Windows؛ **بناء Windows لمشروعنا: غير متحقق (لم يُجرَّب قط).**
عوائق معروفة سلفاً: flutter_qiblah (حساسات) وaudioplayers والإشعارات تحتاج
بدائل/تكييفاً على سطح المكتب. يُقيَّم ضمن خطة المنصة (Web أولاً أولوية).

## 5) macOS — مستقبلية

نفس ملاحظات Windows + متطلبات Apple (توقيع/notarization + sandbox).
غير مستهدفة قبل نضج iPad أولاً.

## 6) Linux — يعمل تطويرياً

المشروع يعمل فعلياً على Linux (بيئة التطوير الحالية — متحقق يومياً).
النشر (Flathub/Snap) غير مستهدف الآن؛ إن استُهدف لاحقاً: تعبئة flatpak +
أيقونات + desktop entry.

## 7) Web / PWA — مخطط (المرحلة التالية بعد الجوال)

موثّق في PLATFORM_DASHBOARD_PLAN. نقاط انتباه من بنائنا الحالي:
- rootBundle للأصول الكبيرة (27MB+) غير عملي على الويب ⇒ يتطلب تحميلاً
  كسولاً/تقسيماً (يتقاطع مع حل H3 — يُحلان معاً).
- Hive يعمل على الويب (IndexedDB) لكن غير مختبر عندنا: **غير متحقق.**
- خطوط PUA (HafsSmart) تعمل على الويب مبدئياً لكن تحتاج تحققاً بصرياً فعلياً.
- PWA: manifest + service worker للـ offline — ينسجم مع فلسفتنا تماماً.

## المستندات القانونية المطلوبة (لكل المنصات)

1. سياسة خصوصية (صفحة ويب عامة، عربي+إنجليزي كحد أدنى).
2. شروط استخدام.
3. صفحة تراخيص/نسب **داخل التطبيق**: KFGQPC EULA (يُرفق كما هو — شرط
   عدم التعديل)، SIL OFL لـ Scheherazade (يتطلب إرفاق نص الرخصة)، IslamHouse،
   مصدر التفسير الميسّر، مصادر بيانات التجويد، محطات الراديو، حزم مفتوحة
   المصدر (تلقائياً عبر أداة licenses).
4. تدفق حذف حساب + صفحة ويب له (مطلب Google).
